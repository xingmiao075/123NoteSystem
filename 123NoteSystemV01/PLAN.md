# 123NoteSystem

> 文件版本：1.8　更新日期：2026-10-16

## 1. 專案概述

123NoteSystem 是一套個人線上筆記系統，讓使用者能快速記下想法，再透過搜尋、標籤與整理狀態找回內容。產品以「先收進來、再整理、需要時找得到」為核心，第一版優先確保個人筆記資料可靠、安全且容易操作，再逐步加入離線、版本歷史與分享協作。

### 目前原型狀態

目前 Flask 原型已具備註冊、登入、筆記新增／編輯／刪除、標題與內文搜尋、標籤、封存、垃圾桶、自動儲存、Email 登入、附件上傳、主題切換、瀏覽器錄音及 SQLite 儲存。密碼重設與正式環境安全設定仍未完成，因此此原型不應直接視為可公開部署版本。

## 2. 產品目標

- 快速建立和編輯筆記，減少記錄過程中的操作負擔。
- 自動保存編輯內容，降低資料遺失風險。
- 已同步保存的草稿不因時間經過而自動過期，並可檢視和還原歷史版本。
- 透過搜尋、標籤與排序，讓筆記容易找回。
- 提供桌面與手機皆可使用的響應式介面。
- 以 Email 作為新帳號的主要登入識別，支援圖片與常見文件附件。
- 讓附件管理與筆記權限一致，僅筆記擁有者可以檢視或下載。
- 讓使用者可直接在筆記編輯器錄製語音、預聽並保存為筆記附件。
- 以明確的使用者資料隔離和存取權限保護筆記。
- 讓使用者能用少量操作完成快速記錄與後續整理。
- 對保存狀態、刪除結果、空列表及錯誤提供清楚回饋，避免不確定感。
- 允許使用者切換並保存個人背景主題，提供多色系與黑白主題且維持文字可讀性。

## 3. 使用者與主要情境

### 目標使用者

需要記錄日常想法、工作備忘、學習摘要或個人資料的個人使用者。

### 核心情境

1. 使用者登入後查看最近更新的筆記。
2. 建立新筆記並輸入標題、內容及標籤。
3. 編輯器自動儲存，並顯示保存狀態。
4. 使用關鍵字搜尋或標籤篩選舊筆記。
5. 誤刪筆記時，從垃圾桶還原。
6. 想法尚未整理時先快速收件，稍後再補標題、標籤或分類。
7. 經常使用的筆記可釘選；已完成但需保留的筆記可封存，不必刪除。

## 4. 功能範圍

### 第一版 MVP

- 註冊、登入、登出；密碼重設需在接妥電子郵件服務後納入發布範圍。
- 新帳號以 Email 註冊與登入，Email 去除前後空白並轉為小寫後唯一；舊帳號在補登 Email 前仍可使用原使用者名稱登入。
- 新增、檢視、編輯及刪除筆記。
- 筆記標題、內文、標籤、建立時間與更新時間；允許只有內容或只有標題的草稿，不強迫先填完才能保存。
- 自動儲存，清楚顯示「儲存中」、「已儲存」或「儲存失敗」，失敗時保留編輯內容並可重試；已保存草稿無自動保留期限。
- 筆記內容每次有實際變更並成功儲存時建立永久版本快照，可檢視歷史並還原；還原會建立新版本而不覆寫舊版本。
- 依標題與內文搜尋筆記。
- 依標籤篩選，並依更新時間、建立時間或標題排序。
- 釘選常用筆記，並可封存已完成但仍需保留的筆記。
- 附加圖片及常見文件，可檢視圖片預覽、下載檔案及移除附件。
- 使用瀏覽器麥克風錄音，提供開始／停止、錄音計時、預聽、重錄及保存至筆記；錄音作為受控音訊附件保存。
- 錄音中斷或 MediaRecorder 發生錯誤時，停止計時、釋放麥克風並顯示可重試的錯誤狀態；不可讓介面卡在錄音中。
- 可在紅、橙、黃、綠、藍、靛、紫、黑、白背景主題間切換；偏好與使用者帳號一同保存，預設為白色。
- 刪除時移至垃圾桶；支援還原與永久刪除。
- 桌面與手機瀏覽器皆可使用，包含載入、空狀態、錯誤及操作成功提示。

### MVP 後增量版本

- 筆記範本（會議記錄、每日紀錄、讀書摘要），支援建立與套用。
- 匯出 Markdown 與 JSON 備份；提供匯入前預覽及重複資料處理方式。
- 離線草稿與重新連線同步；發生衝突時保留兩份內容並讓使用者選擇，不靜默覆寫。
- 自訂主題色票、字體大小及其他編輯器偏好。

### 後續版本

- Markdown 編輯與預覽，或進階文字編輯器。
- 分類資料夾、巢狀頁面及跨筆記反向連結。
- PDF 匯出與多檔批次整理。
- 分享連結及多人協作。
- 跨筆記全文索引與進階搜尋語法。

第一版納入受控的單筆附件上傳，但不同時推出離線同步與多人協作；先透過使用回饋確認使用者確實需要，再投入同步與權限複雜度較高的功能。

## 5. 頁面與介面

- **登入／註冊**：帳號驗證、密碼重設。
- **筆記工作區**：搜尋列、標籤導覽、筆記列表與編輯區。
- **主題選擇器**：以具名色票與可讀標籤切換九種背景主題，明確顯示目前選取狀態。
- **筆記編輯器**：標題、內容、標籤、釘選／封存操作及自動儲存狀態。
- **附件區**：顯示檔名、格式、大小、圖片縮圖、音訊播放器、下載及移除操作；有錄音、上傳中、成功與失敗狀態。
- **封存區**：列出已封存筆記，支援取消封存。
- **垃圾桶**：列出已刪除筆記，提供還原及永久刪除，永久刪除前再次確認。
- **帳號設定**：個人資料、密碼管理與登出。

桌面版採側邊導覽、筆記列表與編輯區的工作區配置；列表寬度固定可調，編輯區優先提供閱讀與輸入空間。手機版以列表和編輯器頁面切換為主，新增筆記保持單手可觸及，避免狹窄畫面塞入多欄。搜尋與篩選在切換頁面後仍保留。

### 介面狀態與操作回饋

- **空白狀態**：首次使用時提供明確的「新增筆記」入口；搜尋無結果時提供清除搜尋操作。
- **載入狀態**：使用固定尺寸的骨架或進度提示，避免內容載入後版面跳動。
- **錯誤狀態**：說明發生什麼事、內容是否已保存，以及可採取的下一步；不只顯示通用錯誤碼。
- **破壞性操作**：垃圾桶清空及永久刪除需二次確認；可還原的刪除提供短暫復原提示。
- **快捷操作**：提供新增筆記與搜尋快捷鍵；快捷鍵不得攔截文字輸入，並在介面中可查詢。
- **長內容**：列表只顯示純文字摘要，編輯器保留原始換行；不將使用者內容當成 HTML 執行。

## 6. 資料模型草案

### `users`

- `id`：使用者識別碼。
- `username`：既有帳號名稱，保留供舊帳號相容登入。
- `email`：新帳號登入識別，允許舊帳號暫時為空；非空值需唯一並正規化為小寫。
- `theme`：使用者背景主題，限於 `red`、`orange`、`yellow`、`green`、`blue`、`indigo`、`violet`、`black`、`white`，預設 `white`。
- `created_at`：建立時間。

密碼與驗證資料應交由成熟的身分驗證方案安全管理，不以明文儲存。

### `notes`

- `id`：筆記識別碼。
- `user_id`：擁有者識別碼。
- `title`：筆記標題。
- `content`：筆記內容。
- `created_at`：建立時間。
- `updated_at`：最後更新時間。
- `is_pinned`：是否釘選，預設為否。
- `archived_at`：封存時間；未封存時為空值。
- `deleted_at`：軟刪除時間；未刪除時為空值。
- 已同步的草稿與筆記都留存在資料庫，不設自動到期時間；只有使用者永久刪除時才刪除筆記及其版本。

### `tags`

- `id`：標籤識別碼。
- `user_id`：標籤擁有者識別碼。
- `name`：標籤名稱。

### `note_tags`

- `note_id`：筆記識別碼。
- `tag_id`：標籤識別碼。

筆記與標籤是多對多關係。第一版可限制標籤名稱在同一使用者下唯一。

### `attachments`

- `id`：附件識別碼。
- `note_id`：所屬筆記識別碼。
- `user_id`：上傳者／擁有者識別碼。
- `original_name`：清理後的原始檔名，僅供顯示。
- `stored_name`：隨機產生的磁碟檔名，不使用使用者提供的路徑。
- `mime_type`、`size_bytes`：檢視與下載所需的媒體類型及檔案大小。
- `created_at`：上傳時間。

### `note_revisions`

- `id`：版本識別碼。
- `note_id`、`user_id`：所屬筆記及擁有者。
- `version_number`：筆記內遞增的版本編號。
- `title`、`content`、`tags_json`：該版本的完整內容與標籤快照。
- `created_at`：版本建立時間。

版本不設自動清理或到期日；只有永久刪除筆記時才級聯刪除其版本。重複保存相同內容不建立新版本。還原歷史時保留所有舊版本，並將還原內容另存為最新版本。

附件檔案存放在應用程式資料目錄外的專用上傳資料夾，資料庫只保存檔案中繼資料。單檔上限 10 MB，接受常見圖片（PNG、JPG、JPEG、GIF、WEBP）、文件（PDF、TXT、CSV、DOCX、XLSX）及音訊（WEBM、OGG、MP4、M4A、MP3、WAV）；拒絕不在白名單的副檔名。永久刪除筆記時同步移除附件資料與實體檔案；移至垃圾桶時保留附件，還原後可繼續使用。

列表預設只查詢未封存且未刪除的筆記；封存區與垃圾桶分開查詢。搜尋預設不包含封存及已刪除筆記，可由使用者切換搜尋範圍。資料表需建立使用者識別碼、更新時間及標籤關聯所需索引；每個查詢仍須檢查筆記擁有者。

## 7. 建議技術架構

以快速交付及容易維護為原則，採用模組化單體架構：

- **前端與應用程式**：Next.js、TypeScript。
- **介面樣式**：Tailwind CSS，搭配一致的表單及編輯器元件。
- **資料庫**：託管 PostgreSQL。
- **驗證**：採用成熟的驗證服務或框架方案，避免自行處理密碼安全細節。
- **部署**：應用程式與資料庫使用託管雲端服務。

初期不拆分微服務。應用程式依認證、筆記、標籤等功能模組組織，等流量或團隊規模有實際需求再調整架構。

目前原型使用 Flask、SQLite 與伺服器端模板；上列為正式版候選架構，不代表要在同一迭代中混用 Flask 與 Next.js。進入 MVP 開發前，先根據團隊熟悉度與部署需求決定「延續 Flask」或「遷移至 Next.js」，並一併決定資料庫方案、登入帳號格式及資料遷移方式。

## 8. 權限與安全要求

- 每筆筆記和標籤都必須綁定使用者。
- 所有讀取、修改、刪除及搜尋操作都必須限制在目前登入使用者的資料範圍內。
- 不得只依賴前端隱藏資料；API 與資料庫查詢也必須檢查擁有者權限。
- 使用安全的工作階段或權杖管理方式，並保護敏感設定與金鑰。
- 上線前移除預設開發密鑰及 debug 模式；設定安全的工作階段 Cookie 與 CSRF 防護。
- 使用 POST 執行登出、刪除及其他會改變資料的操作，不以 GET 觸發狀態變更。
- 限制登入嘗試頻率，並為登入、註冊與筆記內容設定輸入長度上限。
- 對輸入內容進行驗證，避免將不可信內容直接當成 HTML 執行。
- 附件上傳需驗證副檔名、檔案大小及筆記擁有權；以隨機檔名保存，下載時再次驗證擁有者並設定 `Content-Disposition` 與 `X-Content-Type-Options: nosniff`。
- 附件上傳及移除需使用 CSRF 防護；不允許透過使用者提供的檔名形成路徑，也不允許上傳 HTML、SVG 或可執行檔。
- 錄音僅在使用者明確按下開始後請求麥克風權限；停止、保存、離開頁面或發生錯誤時關閉麥克風串流。拒絕權限或瀏覽器不支援時需顯示清楚說明。
- 垃圾桶採軟刪除；永久刪除需明確操作。
- 規劃資料庫備份與錯誤記錄，不在日誌中寫入密碼或敏感筆記內容。

## 9. 自動儲存設計要點

- 使用者停止輸入短暫時間後再送出儲存請求，避免每個字都呼叫 API。
- 送出中顯示「儲存中」，完成後顯示「已儲存」，失敗時提供重試提示。
- 切換筆記或離開編輯器前，避免尚未完成的儲存請求覆蓋較新的內容。
- 儲存 API 應能處理快速連續更新，並以更新時間或版本資訊避免舊請求覆寫新內容。
- 尚未登入時的本機草稿僅作短暫防遺失緩衝；登出或切換帳號時清除，避免共用裝置洩漏內容。
- 自動儲存狀態須以文字呈現並可被螢幕閱讀器讀取；離開頁面前仍有未保存內容時提示使用者。

## 10. 設計原則與互動規格

- **先寫再整理**：新增筆記後可立即輸入；標題可由第一行或日期產生暫時預設值，使用者能再修改。
- **內容優先**：編輯介面減少裝飾和多餘欄位，標題、內文與保存狀態是主要視覺焦點。
- **狀態可預期**：釘選、封存、刪除、保存等狀態需有文字或可辨識圖示，不只靠顏色表示。
- **避免資料意外消失**：刪除可復原；自動儲存失敗、離線或同步衝突時保留草稿並清楚提示。
- **一致且可及**：支援鍵盤操作、可見焦點、標籤化表單、足夠對比度與放大文字；不以顏色作為唯一狀態訊號。
- **響應式優先**：支援窄螢幕、觸控操作及瀏覽器縮放；重要操作不依賴滑鼠 hover。

### 視覺方向

採安靜、清晰、適合長時間閱讀的工作型介面。以中性背景承載內容，使用單一強調色標示主要動作，再以不同狀態色表示成功、警告與錯誤。避免過度卡片化；以清楚的字級層次、留白與分隔線建立資訊結構。內容字體需優先考量繁體中文可讀性與跨平台字型回退。

登入與註冊頁需使用一致的品牌標題、明確的欄位標籤、合理的版面寬度及表單錯誤回饋。筆記工作區和編輯器需沿用相同色彩、字體、按鈕與焦點樣式；附件區須在窄螢幕改為可換行列表，不得造成水平溢出。

主題切換需套用整個網站的色彩系統，包含頁首、頁面背景、面板、文字、連結、主要／次要按鈕、表單、附件、標籤、提示狀態、焦點環與陰影，不可只改內容底色。黑色主題使用深背景和淺色文字，白色主題使用淺背景和深色文字；其餘色系採柔和表面色並搭配同色系強調色。錯誤／警告／成功仍保留可辨識的語意色，但其對比需配合目前主題調整。

## 11. 開發階段

1. **原型補強**：修正預設密鑰、debug 設定、狀態變更請求方式與資料庫初始化策略。
2. **產品基礎**：整理專案設定與資料遷移，確認帳號驗證及擁有者權限。
3. **筆記核心**：完成筆記列表、空白草稿、自動儲存與搜尋。
4. **整理功能**：加入標籤、釘選、封存、垃圾桶與排序。
5. **互動與可及性**：補齊載入、空白、錯誤、成功狀態及桌面／手機操作。
6. **測試與發布**：完成權限測試、核心端對端流程、部署驗收與備份演練。

## 12. MVP 驗收條件

以下項目全部通過，才可判定 MVP 驗收完成：

- [ ] 使用者可註冊、登入及登出；密碼重設在郵件服務啟用後可正常完成，否則不得在介面宣稱可用。
- [ ] 新使用者必須提供有效 Email 註冊；Email 不區分大小寫且不可重複，新帳號可用 Email 登入。
- [ ] 舊資料庫中尚未補登 Email 的帳號仍能以原使用者名稱登入。
- [ ] 登入者可建立、檢視、編輯及刪除自己的筆記，重新整理或重新登入後資料仍存在。
- [ ] 可建立未完成草稿；編輯停止後會自動儲存，保存中、成功、失敗及離線狀態可辨識，失敗時可重試。
- [ ] 已同步至伺服器的草稿不設自動刪除期限，重新登入後仍存在；移至垃圾桶可還原，永久刪除後才清除。
- [ ] 內容有變更並成功儲存時新增版本；相同內容重複儲存不產生重複版本。
- [ ] 使用者可檢視版本內容與時間、還原指定版本；還原後建立新版本，原版本仍可檢視。
- [ ] 快速連續編輯不會被較舊的儲存請求覆寫。
- [ ] 搜尋可比對標題與內文；標籤篩選及更新時間、建立時間、標題排序結果正確。
- [ ] 釘選筆記會顯示在釘選區；封存筆記離開一般列表但可在封存區還原。
- [ ] 軟刪除的筆記不出現在一般列表與搜尋結果，可從垃圾桶還原；永久刪除後無法還原。
- [ ] 使用者無法讀取、修改或刪除其他使用者的筆記，即使自行修改 API 請求中的識別碼也不行。
- [ ] 主要流程在桌面、手機與鍵盤操作下均可完成；焦點明確，放大文字時主要內容與操作仍可用。
- [ ] 首次使用、搜尋無結果、載入失敗及儲存失敗都有對應狀態與恢復路徑。
- [ ] 支援白名單中的圖片與文件上傳、圖片預覽、下載及移除；超過 10 MB 或不支援格式會得到清楚錯誤。
- [ ] 使用者可開始／停止錄音、預聽、重錄並保存為該筆記的音訊附件；重新載入後仍可播放或下載。
- [ ] 麥克風權限被拒絕或瀏覽器不支援錄音時，不會崩潰，且顯示可理解的替代提示。
- [ ] 錄音中發生 MediaRecorder 錯誤時會停止計時、釋放麥克風並允許重試。
- [ ] 未登入者及其他使用者無法透過猜測附件識別碼檢視或下載附件。
- [ ] 登入、註冊、編輯器與附件區在桌面和手機版視覺一致，鍵盤焦點及錯誤提示清晰。
- [ ] 使用者可切換九種具名背景主題，重新整理或重新登入後仍套用已選主題；舊帳號預設白色。
- [ ] 九種主題一致套用於頁首、頁面、面板、文字、連結、按鈕、表單、附件、標籤、狀態提示、焦點環及陰影。
- [ ] 黑色及各彩色主題下，內文、欄位、按鈕、狀態提示與焦點仍清晰可辨。
- [ ] 自動化測試通過，且部署版本已完成一次手動冒煙測試。

## 13. 測試策略與驗收流程

### 測試層級

- **單元測試**：驗證輸入檢查、標籤處理、搜尋條件及筆記狀態等獨立邏輯。
- **整合測試**：驗證 API、資料庫及驗證機制之間的互動，特別檢查使用者資料隔離。
- **端對端測試**：以瀏覽器操作註冊、登入、建立筆記、自動儲存、搜尋、刪除及還原流程。
- **手動冒煙測試**：每次部署後，使用桌面與手機尺寸快速走過登入和核心筆記流程。

### 必測案例

| 編號 | 情境                                     | 預期結果                                       |
| ---- | ---------------------------------------- | ---------------------------------------------- |
| T-01 | 建立筆記並輸入標題與內容                 | 筆記出現在列表，重新載入後內容仍存在           |
| T-02 | 編輯內容後等待自動儲存完成               | 顯示已儲存，資料庫內容為最新內容               |
| T-03 | 模擬儲存請求失敗                         | 顯示失敗狀態，可重試，未儲存內容不會被靜默丟棄 |
| T-04 | 快速連續輸入並送出多個儲存請求           | 最後保存的內容是最新版本                       |
| T-05 | 以標題或內文關鍵字搜尋                   | 只顯示符合條件且屬於目前使用者的筆記           |
| T-06 | 將筆記移至垃圾桶並還原                   | 垃圾桶與一般列表狀態正確切換，內容保留         |

| T-15 | 上傳允許格式圖片／文件並下載             | 檔案內容完整，圖片可預覽，下載名稱安全         |

| T-17 | 儲存未完成草稿並重新登入                 | 草稿仍存在且不因時間經過自動清除               |
| T-18 | 多次保存不同內容後檢視版本歷史           | 每個不同內容快照及建立時間正確顯示             |
| T-19 | 還原較舊版本                             | 筆記回復指定內容，並新增一筆版本而不刪舊版本   |
| T-20 | 永久刪除筆記                             | 筆記、附件及所有版本歷史一併刪除               |
| T-21 | 切換主題、重新整理及重新登入             | 所選主題保留，舊帳號預設白色                   |
| T-22 | 檢查九種主題下文字及操作控制             | 文字對比足夠，欄位、按鈕與焦點可清楚辨識       |

### 驗收流程

1. 開發者在合併前執行單元測試、整合測試及靜態檢查。
2. 對涉及主要使用流程或權限的變更，執行端對端測試。
3. 驗收者依 MVP 驗收清單逐項確認，未通過項目建立缺陷並暫緩發布。
4. 部署到測試環境後執行手動冒煙測試；通過後才部署正式環境。
5. 發布後確認錯誤記錄、登入及筆記儲存功能正常。

## 14. 版本控制與發布

### 程式碼版本控制

- 使用 Git 管理程式碼，將 `.venv/`、環境變數檔、快取、建置輸出及本機資料庫排除在版本庫之外。
- 提供 `.env.example` 作為設定範本；不得提交真實密鑰、密碼或使用者資料。
- `main` 分支只保留可部署版本；功能與修正使用短期分支，完成檢查後透過 Pull Request 合併。
- Pull Request 至少檢查變更內容、測試結果及資料庫遷移影響；權限或資料模型變更需特別檢查回歸風險。
- 提交訊息採用一致格式，例如 `feat: add note search`、`fix: prevent stale autosave`、`docs: update acceptance plan`。
- 發布時建立版本標籤，採用 `MAJOR.MINOR.PATCH`：重大不相容變更提升 MAJOR；新增功能提升 MINOR；相容性修正提升 PATCH。
- 資料庫結構變更使用可追蹤的遷移檔案，不直接手動修改正式資料庫結構；發布前確認備份與回復方案。

### 筆記內容版本控制

- MVP 即保存每次有實際內容變更的標題、內文、標籤與時間快照；相同內容的重複自動儲存不建立新版本。
- 版本依筆記遞增編號，使用者可檢視每版內容與時間，並還原指定版本。
- 還原不覆寫歷史，而是把還原內容另存為最新版本。
- 草稿及版本不設自動保留期限；永久刪除筆記時才一併清除其版本及附件。
- 所有版本讀取與還原均須檢查目前使用者對該筆記的擁有權。
